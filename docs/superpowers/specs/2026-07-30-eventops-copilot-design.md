# EventOps Copilot 产品设计

## 1. 产品目标

EventOps Copilot 面向婚礼、商业活动和校园活动执行人员，将分散的文本、Word、PDF、表格资料转化为有来源、可确认、可执行的活动执行包。产品优先解决信息遗漏、资料冲突、职责不清和变更不同步，不建设售票、签到、营销或供应商交易平台。

## 2. 真实性边界

- 无法获得真实从业者测试与真实业务数据，因此产品不得展示虚构用户、访谈、反馈或效率提升。
- 内置数据全部标注为“合成演示数据”；自动化评测结果仅代表合成数据集。
- README、界面和 Case Study 必须区分：已实现、模拟执行、需配置外部服务、待真实验证。
- 公开 Demo 默认不上传或持久化用户敏感资料。

## 3. 核心用户任务

用户创建活动并导入资料，系统完成：

1. 解析资料并提取活动事实。
2. 为每项事实保留文件、页码或文本位置及原文片段。
3. 将缺失信息和互相冲突的信息列为问题。
4. 在用户确认关键事实后生成时间轴、岗位分工、物料清单和风险预案。
5. 用户逐项审批执行包。
6. 经审批后创建日历任务；未配置真实 OAuth 时只能进行明确标注的模拟调用。
7. 保存运行步骤、修改历史、失败记录、耗时和估算成本。

## 4. MVP 页面

- `/`：项目定位、真实性边界和进入 Demo。
- `/workspace`：活动工作台，包含概览、事实核对、问题、执行包、审批、运行轨迹。
- `/evaluation`：合成评测集结果、指标定义和限制。
- `/case-study`：一页式求职 Case Study。

工作台采用单页分区，不建设复杂路由和多租户后台。演示活动使用“澄屿品牌夏夜发布会”合成案例，故意包含一个时间冲突和三个缺失字段。

## 5. 交互原则

- 首屏先显示活动准备度和阻塞问题，不先展示聊天框。
- 事实按“已确认、待确认、冲突、缺失”显示。
- 所有生成项可展开查看引用；模板建议必须标明“行业模板建议”。
- 外部写操作必须经过单独审批按钮。
- 模拟操作使用琥珀色状态，真实操作使用绿色状态，不能混淆。
- 中文优先，桌面端为主并支持移动端查看。

## 6. 技术架构

采用 Next.js App Router、TypeScript、Tailwind CSS、Vitest 和 Playwright。MVP 使用仓库内版本化 JSON 作为合成演示数据源，通过领域服务层读取和计算，避免部署数据库与账号系统造成范围膨胀。

领域模块分为：

- `domain/types`：活动、事实、问题、交付物、审批、运行轨迹类型。
- `domain/readiness`：准备度与阻塞条件的确定性计算。
- `domain/conflicts`：时间、地点、人员和预算的确定性冲突检测。
- `domain/evaluation`：遗漏率、修改率、任务完成率、工具成功率、耗时和成本指标。
- `lib/ai`：AI 适配器接口；默认使用可复现的合成演示适配器，配置 API 后可接真实模型。
- `lib/calendar`：日历适配器接口；默认模拟，真实 OAuth 接入列为需配置能力。

不在 MVP 中使用多 Agent。产品流程是确定的状态机，单一受控工作流更易审计、评测和控制成本。RAG 在真实模型模式下用于检索用户文档并生成引用；合成 Demo 使用预计算引用以保证公开体验稳定。向量存储生产建议为 PostgreSQL + pgvector，公开作品 Demo 不部署独立向量数据库。

## 7. 数据结构

`EventProject` 包含活动元数据、资料、事实、问题、时间轴、岗位、物料、风险、审批和运行轨迹。所有引用使用 `SourceRef`，至少记录 `documentId`、`documentName`、`locator` 和 `quote`。

生成项具有 `provenance`：

- `source`：直接来自上传资料。
- `template`：来自行业模板建议。
- `human`：由用户确认或修改。

审批状态为 `pending | approved | rejected`。工具调用状态为 `simulated | succeeded | failed`。

## 8. 错误与安全

- 不支持的文件类型在客户端立即拒绝并给出允许格式。
- 解析失败形成失败记录，不生成无来源事实。
- 有阻塞冲突或必填缺项时禁止审批执行包。
- 工具调用使用幂等键；重复点击不得创建重复事件。
- 不在前端或日志输出 API Key、OAuth Token 或完整敏感文档。

## 9. 测试与评测

- 单元测试覆盖准备度、冲突检测、指标计算、审批门槛和幂等键。
- 组件测试覆盖事实来源展开、真实性标签和审批禁用状态。
- Playwright 覆盖首页进入 Demo、查看冲突、完成审批和模拟日历调用。
- 合成评测集至少包含完整资料、缺项资料、冲突资料和无依据生成四类案例。
- 指标页面同时展示公式、样本量、结果和“仅合成评测”声明。

## 10. 交付标准

仓库必须包含本地启动说明、环境变量示例、架构和真实性说明、自动化测试、产品截图、45—60 秒演示视频脚本与成片、一页 Case Study 和可直接用于简历的项目描述。在线 Demo 与 GitHub 发布只有在获得相应账号授权且实际验证成功后才能标记为已发布。
